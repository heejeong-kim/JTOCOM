## 2. 목적

- 커리큘럼 표 자체가 교안 목차가 되도록, 메인 페이지에서 교시별 교안으로 바로 이동함.
- 코딩을 모르는 실무자가 **용어를 알고 → 실제 서비스를 뜯어보고 → 비슷한 서비스를 직접 만드는** 흐름을 따라가게 함.
- 수업 중 바로 복사해 쓸 수 있는 초보자용 프롬프트를 제공함.
- 교육 후에도 수강생이 다시 열어 보는 자료로 남김.

## 7. 교안 구성

### 1교시 바이브코딩과 서비스 기초
1. 바이브코딩이란: 1.1 개념 · 1.2 기존 개발과의 차이(비교 모션) · 1.3 발전 히스토리
2. 바이브코딩을 위한 서비스 기초: 2.1 웹과 앱 · 2.2 서비스는 어떻게 움직이나 · 2.3 데이터 저장 · 2.4 만들고 고치고 공개하기 · 2.5 안전하게 만들기 · 2.6 기획 문서 용어 · 2.7 화면(UI) 용어(레이아웃 1분류 + 컴포넌트 6분류, 53개) · 2.8 용어로 고쳐 보기(samples/ui-practice.html로 "막연하게 vs 용어로" 비교: ① 레이아웃 2단→1단·칩·그리드 3열 ② 탭 필터 + 카드 그리드→캐러셀·인디케이터)
3. 디자인 시스템과 모션: 3.1 디자인 시스템(퓨샷·DESIGN.md·추천 프롬프트) · 3.2 모션(참고 사이트 6개)
4. 오늘의 핵심: 4.1 스스로 점검

### 2교시 뜯어보고 말로 만드는 첫 웹
1. 바이브코딩으로 만든 서비스: 사례 10개 캐러셀
2. 서비스 뜯어보며 이해하기: 2.1 한 번에 뜯어보기(뜯어볼 서비스 후보: 업무 사이트 또는 K-Startup·기업마당·공공데이터포털, 캡처 첨부 또는 URL 직접 입력, ① 핵심 분석(기본) + 예시(펫프렌즈) / ② 서비스 기초 연결 상세 분석(심화) + 예시(국정ON), 참고용 항목별 프롬프트 ①~⑫) · 수업에서는 ① 기본 분석 프롬프트 하나만 쓰고, ② 심화와 참고 12개는 "수업 뒤 혼자 해 보기" 토글
3. 말로 만들고 말로 고치는 첫 웹(만들면서 개념 익히기): 3.1 준비 · 3.2 함께 만들 서비스(지원사업 추천 길잡이) · 3.3 한 번에 만들어 보기 · 3.4 생긴 파일 살펴보기(폴더 구조 5줄 + 앞으로 생길 파일 토글) · 3.5 말로 고쳐 보기(바뀐 파일 확인 + 뜯어본 화면 캡처를 첨부해 헤더·카드 구성 참고해 고치기) · 3.6 변경 이력 남기기(버전·CHANGELOG·되돌리기, ① 첫 버전 저장 ② 고치고 되돌려 보기(선택, 5교시에서 다시 연습), 예시 표)

### 3교시 실무 문제 정의와 PRD
1. 개선 과제 고르기: 1.1 좋은 첫 과제의 기준(반복·범위·크기·데이터·효과, 5열 카드) · 1.2 직무별 과제 예시 6개 · 1.3 AI와 함께 과제 찾기 프롬프트
2. 과제 정의하기(각자 실습): 2.1 사용자·문제·MVP 범위(과제 정의 4줄 + 예시) · 2.2 유저 플로우·데이터 정리 · 2.3 AI가 질문하며 정리하게 하는 프롬프트
3. PRD 1장 만들기(함께 실습): 3.1 함께 만들 PRD 1장(지원사업 추천 길잡이, 예시 CSV 200개 + 공공데이터 API) · 3.2 함께 PRD 만들기(내용이 채워진 프롬프트, 2교시 support-guide 폴더에 저장) · 3.3 내 과제 PRD 만들기(각자, 새 폴더)
4. 프롬프트 작성 원칙: 4.1 좋은 프롬프트 5가지 · 4.2 PRD를 Codex에 전달하기

### 4교시 구현 ① 화면과 데이터
1. PRD로 화면 다듬기(함께): 진행 방식 카드(함께 실습 / 각자 실습) · 1.1 준비(2교시 support-guide 폴더 선택, 고치기 전 버전 저장·CHANGELOG 기록, 공공데이터포털 K-Startup 조회서비스 활용신청) · 1.2 ① PRD와 지금 화면 비교 ② PRD에 맞게 고치기 ③ 컴포넌트 이름으로 고쳐 보기 · 토글: 2교시 화면이 없을 때 첫 화면부터 만들기
2. 데이터 4가지 함께 다루기(함께): 2.1 CSV·JSON·로컬 스토리지·공공데이터 API 비교 · 2.2 ① CSV 불러오기(data/support-programs.csv, 가상 200개) ② JSON 들여다보기 ③ 로컬 스토리지 관심 사업 저장 ④ K-Startup API 최신 공고 탭(인증키는 .env)
3. 내 과제로 연결하기(각자): 3.1 데이터 준비 규칙 4가지 · 3.2 내 과제 연결 프롬프트(4가지 중 필요한 것 추천) + 다른 방법 토글(참고 서비스 기반 범용 프롬프트) · 3.3 공공데이터 연습 파일 2개

### 5교시 구현 ② 핵심 기능
1. 기능 단위로 나누기(개념): 1.1 큰 요청 vs 작은 요청 · 1.2 기능 요청 4줄(채우는 칸 + 예시)
2. 버전과 변경 이력(함께, 2교시 복습 → 기능마다 반복): ① 버전 저장 + CHANGELOG 한 줄 ② 이력 보고 되돌리기 · 심화 토글: Git(커밋 = 이력 한 줄)
3. 함께 기능 더하기(함께): ① 검색 ② 마감일 순 정렬(D-day) ③ 상세 보기 모달
4. 내 과제에 기능 더하기(각자): 4.1 기능 목록 · 4.2 기능 요청 4줄 프롬프트 · 4.3 자주 쓰는 기능 6개

### 6교시 구현 ③ 기능 보완·QA (함께 길잡이로 점검 → 같은 순서로 내 결과물 점검)
1. 핵심 기능 마무리: 1.1 PRD 완료 조건과 비교
2. 디자인·모션 다듬기(구현 후 고도화, 1교시 3번 연결): 2.1 ① 디자인 시스템 추천 → DESIGN.md 저장 ② 화면에 적용(css 위주) ③ 모션 넣기 · 토글: 퓨샷(마음에 드는 화면 3장)
3. 체크리스트로 점검하기: 3.1 QA 체크리스트(기능·입력·화면) · 3.2 ① 길잡이 점검 항목 5개 ② 테스트 시나리오 프롬프트 · 3.3 짝 테스트
4. 오류·불편 고치기: 4.1 오류 알리기 4줄 · 4.2 ① 개발자 도구 콘솔 ② 수정 요청 프롬프트

## 9. 콘텐츠 규칙

- 말투: "~의 전부임", "한 번에 나옴", "흔들리지 않음"처럼 결과를 보장하는 단정 표현은 쓰지 않음. "~하기 쉬움", "~경우가 많음", "더 ~함"처럼 경향으로 씀

- 프로젝트 폴더 구조(2교시 3.2에서 정의, 3~7교시 프롬프트 공통): index.html(뼈대) · css/style.css(꾸밈) · js/script.js(동작) · data/(CSV·JSON·data.js) · assets/ · PRD.md · DESIGN.md(디자인 규칙) · .env(인증키) · versions/(버전) · CHANGELOG.md(변경 이력: 버전 · 날짜·시간 · 바꾼 내용 · 이유, 최신이 맨 위)

- 진행 방식: 1·2교시는 공통, 3교시부터 실무 문제 정의는 각자 하고 PRD부터는 강사와 함께 '지원사업 추천 길잡이'를 만든 뒤(함께 실습), 같은 방법을 내 과제에 연결함(각자 실습). 데이터도 CSV·JSON·로컬 스토리지·공공데이터 API를 함께 해 본 뒤 각자 연결함

- 교안 섹션 패턴(1·2교시 기준): 실습 섹션은 "준비" 체크 → 단계 프롬프트(①②③) 순서, 섹션마다 끝에 "핵심" 한 줄

- 문장은 "~함" 종결어미로 씀.
- 제목·설명은 "서비스"로 쓰고, "웹/앱"은 1교시 2.1 웹과 앱 비교에서만 씀. 실제로 만드는 결과물은 "웹"으로 씀.
- 제목 아래 설명은 개념 문장일 때만 넣고, **한 줄**로 씀.
- 프롬프트는 용어를 모르는 완전 초보자 기준으로 쓰고, AI가 "1교시" 같은 수업 맥락 없이도 이해하게 씀.
- 프롬프트는 특정 기관 사이트가 아니라 어떤 서비스에나 쓸 수 있게 씀.
- 용어는 한국어 + 영문 병기, 1교시 표기를 기준으로 통일함.
  - 레이아웃(Layout) / 컴포넌트(Component) — "부품" 사용 안 함
  - IA(정보 구조) / 메뉴 구조도(Menu Tree) / 사이트맵(Sitemap)은 서로 다른 용어로 구분
  - 유저 플로우(User Flow), 데이터 명세서(Data Specification), 요청(Request)·응답(Response)
- 출처 문구는 화면에 넣지 않음. "공무원" 표현, 근거 없는 수치 추정은 쓰지 않음.
