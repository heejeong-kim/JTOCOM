# 새 업무 추가

업무 인수인계 보드(handover-board)에 새 업무를 넣고, 화면 데이터를 갱신하고, 버전을 남기는 절차임.

## 입력 형식

```
새 업무: 업무명 / 직무 / 주기 / 다음 마감일 / 절차
```

- 다음 마감일은 `YYYY-MM-DD` 형식임.
- 절차는 단계를 ` > `로 구분함. 예: `점검표 출력 > 항목 점검 > 결과 보고`
- 소요 시간, 관련 사이트, 주의할 점은 사용자가 말하지 않으면 비워 둠.

예시:

```
새 업무: 분기 보안 점검 / 공통 행정 / 분기 / 2027-03-15 / 점검표 출력 > 항목 점검 > 결과 보고
```

## 순서

1. **입력 확인**
   - 다섯 값(업무명, 직무, 주기, 다음 마감일, 절차)이 모두 있는지 확인함.
   - 직무는 `공통 행정`, `지원사업 운영`, `보육·공간 운영`, `오픈이노베이션`, `행사·네트워킹`, `성과관리` 중 하나인지 확인함.
   - 주기는 `매주`, `매월`, `분기`, `연 1회`, `수시` 중 하나인지 확인함.
   - 날짜 형식이 맞는지 확인함.
   - 맞지 않는 값이 있으면 추가하기 전에 사용자에게 한 번만 물어봄.
2. **중복 확인**: `data/handover-tasks.csv`에 같은 업무명이 있으면 추가하지 않고 알려 줌.
3. **개인정보 확인**: 사람 이름, 연락처, 주소, 내부 자료로 보이는 값이 있으면 추가하기 전에 알려 주고 바꿀지 물어봄.
4. **CSV에 추가**
   - `data/handover-tasks.csv` 맨 아래에 한 줄을 추가함.
   - 열 순서: 업무명, 직무, 주기, 다음 마감일, 소요 시간(분), 절차, 관련 사이트, 주의할 점
   - 쉼표가 들어간 값은 큰따옴표로 감쌈.
   - 기존 줄과 파일 인코딩(UTF-8)은 바꾸지 않음.
5. **화면 데이터 갱신**: `data/data.js`를 CSV 기준으로 다시 만듦.
6. **버전 저장**
   - CHANGELOG.md를 보고 다음 번호로 `versions/` 안에 새 폴더를 만들어 지금 파일을 복사함. `versions/` 폴더와 `.env` 파일은 빼고 복사함.
   - CHANGELOG.md 맨 위에 한 줄을 추가함: `버전 / 날짜·시간 / 새 업무 추가: {업무명} / 인수인계 보드에 업무 추가`
7. **결과 알리기**: 쉬운 말로 3줄 이내로 알려 줌.
   - 추가한 업무
   - 바뀐 파일
   - 확인 방법: 브라우저 새로고침 → 검색창에 업무명 입력

## 하지 않는 것

- 기존 업무를 고치거나 지우지 않음.
- 화면 디자인이나 다른 기능을 바꾸지 않음.
- 원본 CSV의 열 이름이나 순서를 바꾸지 않음.
