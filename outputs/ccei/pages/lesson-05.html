함께 실습

버전과 변경 이력

2.1 기능마다 버전과 이력 남기기

2교시에 해 본 변경 이력 관리를 기능마다 반복함. 기능 하나가 완성될 때마다 버전을 저장하고 이력을 한 줄 남김.

  1. ① 버전 저장하고 이력 남기기

    지금 상태를 다음 번호의 새 버전으로 저장해줘. (예: v06-검색)
이유: {왜 바꿨는지}

  2. ② 이력 보고 되돌리기

    CHANGELOG.md를 표로 보여 줘.
내가 고른 버전으로 되돌려줘: {예: v05-공휴일}
되돌리기 전에 무엇이 바뀌는지 먼저 알려 주고, 되돌린 것도 CHANGELOG.md에 새 버전으로 한 줄 남겨줘.
심화 · Git으로 이력 관리하기

깃(Git)은 버전과 변경 이력을 자동으로 남기는 도구임. 저장 하나가 커밋(Commit)이고, 커밋 메시지가 CHANGELOG 한 줄과 같은 역할을 함. "이 폴더에서 Git을 시작하고 지금 상태를 커밋해줘. Git이 없으면 설치 방법부터 알려줘."라고 요청하면 됨. 설치에 관리자 권한이 필요할 수 있음.

핵심 기능 하나 = 버전 하나 = 이력 한 줄. 이렇게 쌓아 두면 실패했을 때 돌아갈 곳을 고르기 쉬움.
함께 실습

함께 기능 더하기

3.1 함께 더할 기능 3가지

  1. ① 검색

    기능 하나만 만들어줘.
기능 이름: 검색
사용자 행동: 목록 위 검색창에 단어를 입력함
기대 결과: 업무명이나 절차에 그 단어가 들어간 카드만 보임
확인 방법: "보고"를 입력하면 카드 수가 줄어들고, 없는 단어면 안내 문구가 나옴

  2. ② 마감 임박 순 정렬

    기능 하나만 만들어줘.
기능 이름: 마감 임박 순 정렬
사용자 행동: '마감 임박 순' 버튼을 누름
기대 결과: 다음 마감일이 가까운 업무부터 보이고, 이번 주에 마감인 카드는 테두리가 강조됨
확인 방법: 버튼을 누르면 맨 앞 카드의 마감일이 가장 빠름

  3. ③ 인수인계서 한 장 보기

    기능 하나만 만들어줘.
기능 이름: 인수인계서 한 장 보기
사용자 행동: '인수인계서' 버튼을 누름
기대 결과: 모든 업무를 직무·주기별로 묶어 업무명, 다음 마감일, 절차, 주의할 점을 한 장으로 보여 주고, 인쇄 버튼으로 출력할 수 있음
확인 방법: 인쇄 미리보기에서 직무별로 나뉘고, 표가 페이지 중간에 잘리지 않음
  • 기능 하나가 끝날 때마다 새로고침해서 확인 방법대로 눌러 봄
  • 잘 되면 2.1 ①로 버전을 저장하고 이력을 남긴 뒤 다음 기능으로 넘어감

3.2 강사 시연 · 반복 작업을 스킬로 묶기

기능을 더할 때마다 같은 순서를 반복했음. 이렇게 매번 같은 순서로 하는 일은 스킬(Skill)로 묶어 두면 한 줄로 부를 수 있음. 강사가 '새 업무 추가' 스킬을 시연함.

AGENTS.md

늘 지키는 규칙

Codex가 작업 전에 항상 읽음

예시
쉬운 말로 설명, 파일 구조, 요청한 것만 고치기
Skill

필요할 때 꺼내 쓰는 절차

부르거나 필요할 때만 불러와 그대로 따라 함

예시
"새 업무:" 한 줄 → CSV 추가 → 화면 갱신 → 버전 저장
심화 · 반복 작업을 스킬로 만들기 (수업 뒤 혼자 해 보기) 
이 폴더에서 쓸 스킬을 하나 만들어줘.
스킬 이름: 새 업무 추가
언제 쓰나: 내가 '새 업무:'로 시작해 업무 이름, 직무, 주기, 다음 마감일, 절차를 말할 때
하는 일:
1. data/handover-tasks.csv에 한 줄을 추가함
2. data/data.js를 다시 만듦
3. 화면에서 새 업무를 확인하는 방법을 알려 줌
4. 새 버전으로 저장하고 CHANGELOG.md에 기록함
다 만들면 이 스킬을 어떻게 부르는지 알려줘.

직접 만들기 어렵다면 완성된 스킬 파일을 내려받아 프로젝트 폴더의 .agents/skills/new-task/ 폴더에 넣어도 됨.

  • SKILL.md 새 업무 추가 스킬

만든 뒤에는 이렇게 한 줄로 씀: "새 업무: 분기 보안 점검 / 공통 행정 / 분기 / 2027-03-15 / 점검표 출력 > 항목 점검 > 결과 보고"

핵심 요청 → 확인 → 버전 저장·이력 기록을 기능마다 반복함.

내 과제에 기능 더하기

4.1 내 과제의 기능 목록 만들기

PRD.md의 완료 조건을 읽고, 아직 없는 기능을 작은 단위로 나눠줘.
- 기능 하나는 10분 안에 만들고 확인할 수 있는 크기로 나눠줘.
- 사용자에게 가장 중요한 기능부터 순서를 매겨줘.
- 표로 보여 줘: 순서 / 기능 이름 / 사용자 행동 / 확인 방법
- 아직 코드는 만들지 말아줘.

4.2 기능 하나씩 만들기

기능 하나만 만들어줘.
기능 이름: {무엇을 만들지}
사용자 행동: {사용자가 무엇을 하는지}
기대 결과: {그러면 무엇이 보이는지}
확인 방법: {내가 어떻게 눌러 확인할지}

4.3 자주 쓰는 기능

필터 · Filter"주기 버튼을 누르면 그 주기 업무만 보여 줘"
정렬 · Sort"소요 시간이 긴 순으로 정렬해줘"
상세 보기 · Modal"업무를 누르면 주의할 점을 팝업으로 보여 줘"
입력 폼 · Form"새 업무를 입력해 목록에 더하게 해줘"
합계 · Summary"이번 달 마감 업무 수를 위에 카드로 보여 줘"
내보내기 · Export"지금 보이는 업무 목록을 CSV로 내려받게 해줘"
핵심 함께 만든 순서 그대로 4줄로 요청하고, 확인하고, 이력을 남기며 저장함.
