기능 단위로 나누기

1.1 큰 요청 대신 작은 요청

AI는 한 번에 하나를 요청할 때 가장 정확하게 만듦.

아쉬운 예

한 번에 다 요청

요청
"검색, 필터, 즐겨찾기, 엑셀 저장 다 넣어줘"
결과
어디가 고장 났는지 찾기 어려움
좋은 예

기능 하나씩 요청

요청
"먼저 검색 기능만 만들어줘"
결과
확인하고 저장한 뒤 다음 기능으로 넘어감

1.2 기능 목록과 순서 정하기

PRD.md의 완료 조건을 읽고, 아직 없는 기능을 작은 단위로 나눠줘.

- 기능 하나는 10분 안에 만들고 확인할 수 있는 크기로 나눠줘.
- 사용자에게 가장 중요한 기능부터 순서를 매겨줘.
- 표로 보여 줘: 순서 / 기능 이름 / 사용자가 하는 행동 / 확인 방법
- 아직 코드는 만들지 말아줘.
핵심 기능 하나는 10분 안에 만들고 확인할 수 있는 크기로 나눔.
실습

한 기능씩 만들기

2.1 기능 요청 4줄

기능 하나를 요청할 때는 아래 4줄을 채워서 말함.

기능 목록의 {순서 번호}번 기능만 만들어줘.

기능 이름: {예: 검색}
사용자가 하는 행동: {예: 검색창에 단어를 입력함}
기대하는 결과: {예: 이름에 그 단어가 들어간 카드만 보임}
확인 방법: {예: "창업"을 입력하면 카드 수가 줄어듦}

다른 기능은 건드리지 말고, 다 만들면 내가 직접 확인할 순서를 알려줘.

2.2 자주 쓰는 기능

검색 · Search"이름으로 찾을 수 있게 검색창을 만들어줘"
필터 · Filter"단계 버튼을 누르면 그 단계만 보여 줘"
정렬 · Sort"마감일이 가까운 순으로 정렬해줘"
상세 보기 · Modal"카드를 누르면 자세한 내용을 팝업으로 보여 줘"
즐겨찾기 · LocalStorage"별표를 누른 항목을 새로고침해도 기억하게 해줘"
내보내기 · Export"지금 보이는 목록을 CSV로 내려받게 해줘"

2.3 만들 때마다 확인하기

  • 브라우저를 새로고침해서 바뀐 화면을 봄
  • 2.1에 적은 확인 방법대로 직접 눌러 봄
  • 잘 되면 저장하고, 안 되면 오류 내용을 그대로 알려 줌
핵심 기능 요청 4줄로 하나씩 만들고, 만들 때마다 직접 눌러 확인함.

저장하고 되돌리기

3.1 저장 지점 만들기

깃(Git)은 파일의 저장 지점을 남겨 두는 도구이고, 저장 지점 하나를 커밋(Commit)이라고 함.

  1. ① 처음 한 번 · Git 시작

    이 폴더에서 Git을 시작해줘. Git이 설치되어 있지 않으면 설치 방법을 쉬운 말로 먼저 알려줘.
지금 상태를 "첫 화면 완성"이라는 이름으로 저장해줘.
나는 Git을 모르니 명령어 설명 없이 결과만 알려줘.

  2. ② 잘 되면 · 저장

    지금 상태를 저장해줘.
저장 이름: {예: 검색 기능 완성}

  3. ③ 안 되면 · 되돌리기

    방금 바꾼 내용이 마음에 들지 않아.
마지막으로 저장한 상태로 되돌려줘.
되돌리기 전에 무엇이 사라지는지 먼저 알려줘.

3.2 저장 기록 보기

지금까지 저장한 기록을 최근 것부터 표로 보여 줘.
저장 이름 / 저장한 시각 / 바뀐 파일 수
Git이 어렵다면

기능이 잘 될 때마다 프로젝트 폴더를 통째로 복사해 "폴더이름_검색완성"처럼 이름을 붙여 두는 것도 같은 효과가 있음.

핵심 한 번에 하나 만들고, 잘 되면 저장, 안 되면 저장 지점으로 되돌림.
