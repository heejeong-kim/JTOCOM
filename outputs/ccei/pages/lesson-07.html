실습

결과물 시연

1.1 3분 시연 순서

인수인계 보드나 내 결과물로 조 안에서 한 사람씩 3분, 조마다 한 명이 전체 앞에서 핵심 행동만 2분 시연합니다.

30초

문제

말하기
누가 어떤 불편을 겪었는지
30초

해결 방법

말하기
그래서 무엇을 만들었는지 한 줄로
1분 30초

핵심 행동 시연

보여 주기
사용자가 끝내려는 일을 처음부터 끝까지
30초

배운 점

말하기
잘된 점 하나, 다음에 할 일 하나

1.2 시연 준비하기

  1. ① 시연 대본 만들기

    PRD.md와 지금 만든 화면을 바탕으로 3분 시연 대본을 만들어줘.
순서: 문제(30초) → 해결 방법(30초) → 핵심 행동 시연(1분 30초) → 배운 점(30초)
- 말하듯이 쉬운 문장으로 써줘.
- 시연할 때 누를 버튼 순서를 따로 번호로 적어줘.

  2. ② 시연 직전 확인

    • 화면을 새로고침해서 처음 상태로 둠
    • 브라우저 창을 크게 하고 글자 크기를 키움
    • 시연 화면에 실제 개인정보나 인증키가 보이지 않는지 다시 봄
    • 잘 안 될 때를 대비해 캡처 화면을 한 장 준비함
핵심 문제 → 해결 → 시연 → 배운 점 순서로 말하면 3분 안에 전달하기 쉬움.

2.1 KPT 회고

KPT는 Keep(계속할 것), Problem(막힌 것), Try(다음에 해 볼 것)로 돌아보는 방법입니다.

Keep

잘된 점

계속 가져갈 방법

예시
기능을 하나씩 요청하니 덜 꼬였음
Problem

막힌 점

시간이 많이 든 곳

예시
공휴일을 빼고 D-day를 계산하는 부분이 처음에 틀렸음
Try

다음에 해 볼 것

바로 시도할 한 가지

예시
내 과제를 PRD부터 같은 순서로 만들기

2.2 회고 정리하기

오늘 이 프로젝트를 만든 과정을 회고하고 싶어.
CHANGELOG.md의 변경 이력과 내 메모를 보고 KPT로 정리해줘.

내 메모: {잘된 점, 막힌 점을 자유롭게}

Keep / Problem / Try 각각 2줄 이내로, 마지막에 '다음에 쓸 프롬프트 한 줄'도 적어줘.
핵심 Try 한 가지를 정해 두면 다음 바이브코딩을 시작하기가 쉬워짐.

3.2 업무에 쓰기 전 확인

  • 기관의 정보보안 규정과 승인 절차를 먼저 확인함
  • 실제 개인정보·내부 자료는 승인 전까지 넣지 않음
  • 외부에 공개하기 전 담당 부서와 함께 검토함
  • 고장 났을 때 누가 고칠지 정해 둠

3.3 자주 묻는 질문

Codex 없이도 계속 고칠 수 있나요?

다른 AI 코딩 도구에서도 같은 프로젝트 폴더와 PRD.md·AGENTS.md를 열고 같은 방식으로 요청하면 이어서 고칠 수 있음.

다음 담당자는 어떻게 이어받나요?

프로젝트 폴더(.env 파일 제외)와 인수인계 파일(handover.json)을 함께 넘기면, 다음 담당자가 폴더를 열고 '인수인계 파일 불러오기'로 진행 상태까지 이어서 씀.

다른 사람에게 보여 주려면 어떻게 하나요?

.env 파일을 뺀 뒤 프로젝트 폴더를 압축해 전달하거나, 승인을 받은 뒤 정적 웹 호스팅(Static Hosting)으로 공개할 수 있음. 공개 전에는 6교시 보안 체크를 다시 함.

데이터가 바뀌면 어떻게 하나요?

새 CSV를 data 폴더에 같은 이름으로 넣고 "data/data.js를 새 파일 기준으로 다시 만들어줘"라고 요청함. 공휴일은 새해 공휴일 파일로 바꿔 넣고 "D-day를 다시 계산해줘"라고 요청함.

여러 명이 함께 고칠 수 있나요?

깃허브(GitHub) 같은 저장소에 올리면 함께 고칠 수 있음. 처음에는 한 사람이 고치고 나머지는 의견을 주는 방식이 안전함.

핵심 오늘 만든 웹은 끝이 아니라 첫 버전이고, 쓰는 사람의 의견으로 다음 버전을 만듦.
