함께 만든 인수인계 보드로 먼저 점검하고, 같은 순서로 내 과제 결과물도 점검합니다.

1.1완료 조건과 비교하기

PRD.md의 완료 조건과 지금 만든 화면을 비교해줘.

"안 됨"이 있으면 기능 요청 4줄로 하나씩 마무리합니다.

핵심 PRD 완료 조건이 모두 되면 기능 만들기는 멈추고 점검으로 넘어갑니다.

디자인·모션 다듬기

2.1디자인 시스템 정하고 적용하기

디자인 시스템(Design System)과 모션(Motion)으로 화면을 다듬습니다.

  1. ① 디자인 시스템 정하기

    이 폴더의 PRD.md를 읽고, 이 서비스에 어울리는 디자인 시스템 방향을 2가지 추천하고 각각 왜 어울리는지 쉬운 말로 알려줘.
내가 하나를 고르면 색, 글자 크기, 여백, 컴포넌트(버튼·카드 등) 모양을 표로 정리해서 DESIGN.md 파일로 저장해줘.

  2. ② 화면에 적용하기

    DESIGN.md 규칙대로 지금 화면을 다듬어줘.
- 기능은 바꾸지 말고 css/style.css 위주로 고쳐줘.
- 바뀐 점을 전·후로 3줄 알려줘.

  3. ③ 모션 넣기 선택

    화면에 움직임(모션)을 넣어줘.
버튼에 마우스를 올리면 0.2초 동안 부드럽게 색이 바뀌고, 업무 상세가 열릴 때는 빨리 열리고 천천히 멈추게 해줘.
움직임은 과하지 않게 하고, 휴대폰이나 컴퓨터에서 '움직임 줄이기'를 켠 사람에게는 움직이지 않게 해줘.
마음에 드는 디자인 예시가 있다면

①을 쓰는 대신, 마음에 드는 화면 3장을 캡처해 첨부하고 "세 화면에 공통으로 쓰인 특징을 찾아 디자인 시스템을 만들고 DESIGN.md로 저장해줘"라고 요청합니다 (퓨샷 · Few-shot).

내 과제로 연결한 사람은 같은 순서로 내 폴더에 DESIGN.md를 만들어 적용합니다.

핵심 DESIGN.md 하나로 규칙을 정해 두면 화면을 고쳐도 디자인을 일관되게 유지하기 쉽습니다.

3.2함께 점검하기

  1. ① 인수인계 보드로 직접 해 보기

    • 직무 "행사·네트워킹", 주기 "매월"을 고르면 맞는 업무만 보입니다
    • 검색창에 없는 단어를 넣으면 안내 문구가 나옵니다
    • 절차를 체크하고 새로고침해도 진행 상태가 남습니다
    • 인수인계 파일을 내보낸 뒤 시크릿 창에서 불러와도 같은 내용이 보입니다
    • 공휴일이 낀 마감일의 D-day가 맞습니다

  2. ② 테스트 시나리오 만들기

    PRD.md의 사용자와 유저 플로우를 보고, 내가 직접 따라 해 볼 테스트 순서를 만들어줘.
- 정상적으로 쓰는 경우 3개
- 실수하는 경우 3개 (빈 값, 잘못된 값, 결과 없음 등)
표로 보여 줘: 번호 / 이렇게 해 보기 / 이렇게 보이면 정상

    내 과제 폴더에서도 같은 프롬프트로 해 봅니다.

3.3짝 테스트

  • 옆 사람에게 설명 없이 화면만 보여 주고 핵심 행동을 해 보게 합니다
  • 막히거나 머뭇거린 곳을 그대로 메모합니다
  • 메모를 4번 섹션의 오류 알리기 형식으로 정리합니다
핵심 처음 쓰는 사람의 눈으로 써 보면 만든 사람이 놓친 문제가 잘 보입니다.

4.2오류 찾아 고치기

  1. ① 오류 메시지 찾기

    개발자 도구(Developer Tools)의 콘솔(Console) 탭에 빨간 글씨로 오류가 나옵니다.

    WindowsF12 또는 Ctrl+Shift+I
    MacCmd+Option+I
    복사빨간 글씨를 그대로 복사해 붙여 넣습니다

  2. ② 고쳐 달라고 하기

보안 확인

5.1공유 전 보안 체크

  • 실제 개인정보(이름, 연락처, 주소 등)가 데이터에 없습니다
  • 인증키(API Key)가 코드·화면에 없고 .env 파일에만 있습니다
  • 내부 문서·미공개 자료가 들어 있지 않습니다
  • 입력한 내용이 외부로 전송되지 않습니다
  • 내보낸 인수인계 파일(handover.json)에 개인정보·내부 자료가 없습니다

5.2AI에게 보안 점검 맡기기

이 프로젝트 폴더 전체를 보안 관점에서 점검해줘.
1. 개인정보로 보이는 값
2. 인증키·비밀번호처럼 보이는 값 (.env 파일 밖에 있는 것)
3. 외부 주소로 데이터를 보내는 코드
4. 내보낸 인수인계 파일(handover.json)에 들어가는 내용 중 개인정보나 내부 자료로 보이는 값
찾은 것을 파일 이름과 함께 표로 보여 주고, 고치기 전에 나에게 먼저 물어봐줘.

내 과제 폴더에서도 같은 프롬프트로 점검합니다.

핵심 다른 사람에게 보여 주기 전에 보안부터 확인합니다.
