개선 과제 고르기

1.1 좋은 첫 과제의 기준

첫 과제는 작고, 자주 하고, 혼자 바꿀 수 있는 일에서 고름.

반복

자주 반복되는 일

매주·매달 같은 일을 손으로 반복함

예시
점수 엑셀 합산, 참가자 명단 정리
확인
"이 일을 한 달에 몇 번 하나?"
범위

내 선에서 바꿀 수 있는 일

결재·시스템 변경 없이 혼자 써 볼 수 있음

예시
내 업무용 정리표, 안내 페이지
확인
"승인 없이 오늘 써 볼 수 있나?"
크기

화면 3개 이하

핵심 행동 하나로 끝나는 작은 도구

예시
입력 → 결과 한 화면
확인
"버튼 한두 번으로 끝나나?"
데이터

공개해도 되는 데이터

개인정보·내부 비공개 자료 없이 만들 수 있음

예시
공공데이터, 가상 예시 데이터
확인
"이름·연락처 없이 되나?"
효과

바로 보이는 효과

줄어드는 시간이나 실수가 분명함

예시
30분 걸리던 집계가 1분
확인
"끝나면 무엇이 줄어드나?"

1.2 직무별 과제 예시

지원사업 운영평가점수 집계·순위 도구: 심사위원 점수를 넣으면 합계와 순위가 자동 계산됨
보육·공간 운영입주기업 현황판: 입주기업을 분야·층별로 걸러 봄
오픈이노베이션수요-기술 매칭 보드: 대기업 수요와 스타트업 기술을 키워드로 이어 봄
행사·네트워킹참가자 관리·명찰 출력: 명단을 불러와 명찰을 한 번에 만듦
원스톱 상담지원사업 추천 길잡이: 조건을 고르면 맞는 지원사업을 보여 줌
성과관리보육기업 성과 대시보드: 매출·고용 변화를 한눈에 봄

1.3 AI와 함께 과제 찾기

나는 코딩을 모르는 초보자야. 내 업무를 설명할 테니, 바이브코딩으로 만들어 볼 작은 웹 도구 아이디어 3개를 추천해줘.
내 업무: {내가 맡은 일, 자주 반복하는 일, 불편한 점}

아래 기준에 맞는 아이디어만 골라줘.
- 자주 반복되는 일을 줄여 줄 것
- 결재나 시스템 변경 없이 나 혼자 써 볼 수 있을 것
- 화면 3개 이하, 버튼 한두 번으로 끝날 것
- 개인정보나 내부 비공개 자료 없이 공개 데이터나 가상 데이터로 만들 수 있을 것

아이디어마다 '이름 | 누가 쓰나 | 무엇이 줄어드나 | 핵심 행동 하나'를 표로 정리하고, 그중 첫 과제로 가장 좋은 하나를 추천해줘.

과제 정의하기

2.1 사용자 · 문제 · MVP 범위

MVP(Minimum Viable Product)는 핵심 행동 하나가 되는 가장 작은 첫 버전임.

채우는 칸

과제 정의 4줄

누가
이 도구를 쓰는 사람
어떤 불편
지금 무엇이 오래 걸리거나 틀리는지
핵심 행동
사용자가 끝내려는 일 하나
이번에 안 할 것
로그인, 실제 저장, 결재 연동 등
예시

지원사업 추천 길잡이

누가
지원사업을 찾는 예비·초기 창업자
어떤 불편
공고가 많아 내 조건에 맞는 사업을 찾기 어려움
핵심 행동
창업 단계와 업종을 고르면 맞는 사업을 봄
이번에 안 할 것
신청 접수, 회원가입, 실제 공고 연동

2.2 유저 플로우 · 데이터 정리

유저 플로우 · User Flow

화면이 넘어가는 순서

예시
홈 → 조건 선택 → 추천 결과 → 사업 상세
기준
화면 3개 이하, 화살표 3번 이하
데이터 항목 · Data

화면에 보여 줄 정보

예시
사업명, 지원 대상, 창업 단계, 업종, 지원 내용, 마감일
기준
항목 6개 안팎, 개인정보 없음

2.3 AI가 질문하며 정리하게 하기

나는 코딩을 모르는 초보자야. 내가 만들고 싶은 작은 웹 도구를 함께 정리하고 싶어.
만들고 싶은 것: {도구 이름과 한 줄 설명}

나에게 질문을 한 번에 하나씩 해서 아래 5가지를 함께 정해줘. 내가 모르겠다고 하면 예시를 2~3개 보여 주고 고르게 해줘.
1. 누가 쓰는지
2. 지금 어떤 불편이 있는지
3. 사용자가 끝내려는 핵심 행동 하나
4. 화면이 넘어가는 순서(유저 플로우, 화면 3개 이하)
5. 화면에 보여 줄 데이터 항목(개인정보 제외)

다 정해지면 '이번에 안 할 것'까지 포함해 표 하나로 정리해줘.

PRD 1장 만들기

3.1 PRD 1장의 구성

PRD(Product Requirements Document)는 무엇을, 누구를 위해, 어디까지 만들지 적은 한 장짜리 약속임.

예시 · PRD 1장

지원사업 추천 길잡이

서비스 이름
지원사업 추천 길잡이
목적
내 조건에 맞는 지원사업을 1분 안에 찾게 함
사용자
지원사업을 찾는 예비·초기 창업자
문제
공고가 많고 흩어져 있어 맞는 사업을 찾기 어려움
핵심 기능
창업 단계·업종 선택 → 맞는 사업 카드 목록 → 상세 보기
MVP 범위
가상 사업 데이터 10개, 화면 안에서만 동작 (로그인·저장·신청 제외)
유저 플로우
홈 → 조건 선택 → 추천 결과 → 사업 상세
데이터
사업명, 지원 대상, 창업 단계, 업종, 지원 내용, 접수 마감일
완료 조건
조건을 고르면 맞는 사업만 보이고, 없으면 안내 문구가 나옴

3.2 PRD 작성 프롬프트

앞에서 정리한 내용을 바탕으로 PRD(제품 요구사항 문서) 1장을 만들어줘. 나는 코딩을 모르는 초보자라서 쉬운 말로 써줘.
정리한 내용: {2.3에서 받은 정리 표를 그대로 붙여 넣기}

아래 9개 항목을 표로 정리해줘.
서비스 이름 | 목적 | 사용자 | 문제 | 핵심 기능 | MVP 범위(이번에 안 할 것 포함) | 유저 플로우 | 데이터 항목 | 완료 조건

- 완료 조건은 "무엇을 하면 무엇이 보이면 완성"처럼 직접 눌러 확인할 수 있게 써줘.
- 개인정보나 내부 비공개 자료가 들어가 있으면 빼고 알려줘.
- 다 만들면 이 내용을 PRD.md 파일로 이 폴더에 저장해줘.
  • 실습 폴더에 PRD.md 파일이 생겼는지 확인함
  • 완료 조건을 읽고 직접 눌러 확인할 수 있는 문장인지 확인함

프롬프트 작성 원칙

4.1 좋은 프롬프트의 5가지

① 맥락

누구인지·무엇을 하는지

아쉬운 예
"웹 만들어줘"
좋은 예
"나는 초보자야. 창업자가 지원사업을 찾는 도구를 만들고 싶어"
② 목표 하나

한 번에 하나만 요청

아쉬운 예
"화면, 데이터, 로그인, 디자인 다 해줘"
좋은 예
"먼저 조건 선택 화면만 만들어줘"
③ 조건

지킬 것과 하지 말 것

아쉬운 예
조건 없이 요청
좋은 예
"로그인·실제 저장은 하지 말고, 개인정보는 쓰지 마"
④ 예시

원하는 모습을 보여 주기

아쉬운 예
"예쁘게 해줘"
좋은 예
"카드처럼, 마감일은 빨간 글씨로"
⑤ 확인 방법

끝났는지 아는 기준

아쉬운 예
"잘 되게 해줘"
좋은 예
"조건을 고르면 맞는 카드만 보이면 완성이야"

4.2 PRD를 Codex에 전달하기

나는 코딩을 모르는 초보자야. 이 폴더의 PRD.md를 먼저 읽어줘.
아직 코드는 만들지 말고, 아래 3가지만 쉬운 말로 알려줘.
1. PRD를 읽고 이해한 내용을 3줄로 요약
2. MVP를 만들기 위한 작업 순서(3~5단계, 단계마다 확인할 것 포함)
3. PRD에서 빠졌거나 애매해서 내가 정해야 할 것

내가 확인하고 '1단계 시작'이라고 말하면, 그때부터 한 단계씩 만들어줘.
핵심 PRD 1장이 곧 AI에게 주는 설계도이고, 좋은 프롬프트는 그 설계도를 한 조각씩 꺼내 쓰는 것임.
