1.1좋은 프롬프트의 5가지

맥락·목표·조건·예시·확인 방법을 넣으면 원하는 결과에 가까워지기 쉽습니다.

① 맥락

누구인지·무엇을 하는지

아쉬운 예
"웹 만들어줘"
좋은 예
"나는 초보자야. 입주기업에 맞는 지원사업 공고를 찾아 주는 레이더를 만들고 싶어"
② 목표 하나

한 번에 하나만 요청

아쉬운 예
"화면, 데이터, 로그인, 디자인 다 해줘"
좋은 예
"먼저 공고 목록 화면만 만들어줘"
③ 조건

지킬 것과 하지 말 것

아쉬운 예
조건 없이 요청
좋은 예
"로그인·실제 저장은 하지 말고, 개인정보는 쓰지 마"
④ 예시

원하는 모습을 보여 주기

아쉬운 예
"예쁘게 해줘"
좋은 예
"카드처럼, 마감이 3일 안 남은 공고는 빨간 글씨로"
⑤ 확인 방법

끝났는지 아는 기준

아쉬운 예
"잘 되게 해줘"
좋은 예
"키워드를 넣으면 맞는 공고만 마감 순으로 보이면 완성이야"

  • 실제 이름·연락처·내부 자료는 빼고 보냅니다

아래 기준에 맞는 아이디어만 골라줘.
- 자주 반복되는 일을 줄여 줄 것
- 결재나 시스템 변경 없이 나 혼자 써 볼 수 있을 것

아이디어마다 '이름 | 누가 쓰나 | 무엇이 줄어드나 | 핵심 행동 하나'를 표로 정리하고, 그중 첫 과제로 가장 좋은 하나를 추천해줘.

처음에는 업무 전체를 한 번에 자동화하기보다, 반복 작업 하나를 줄이는 작은 도구가 만들고 시험하기 좋아요. 아래 3개는 모두 화면 3개 이하로, 공개 공고나 가상 기업 데이터만으로 혼자 써 볼 수 있어요.

이름누가 쓰나무엇이 줄어드나핵심 행동 하나
주간 지원사업 브리핑 메이커매주 팀 공유 자료를 만드는 센터 담당자공고 내용을 다시 요약하고 형식을 맞추는 작업공개 공고 내용을 넣고 ‘브리핑 만들기’를 눌러 복사하기
공고–기업 매칭 도우미기업별로 적합한 공고를 고르는 센터 담당자기업의 분야·창업 단계를 공고 조건과 반복 대조하는 작업공고를 선택하고 ‘추천 기업 보기’를 눌러 가상 기업별 매칭 이유와 안내 문구 확인하기
기업별 안내 기록장어떤 기업에 무엇을 안내했는지 관리하는 센터 담당자중복 안내와 지난 발송 내역을 찾아보는 작업가상 기업과 공개 공고를 선택해 ‘안내 완료’로 기록하기

첫 과제로는 ‘주간 지원사업 브리핑 메이커’를 추천해요.

공고 내용 입력 → 브리핑 결과, 화면 2개로 시작할 수 있고, 실제로 작성한 브리핑과 비교해 쓸 만한지 바로 판단할 수 있어요. 처음에는 사이트 자동 수집 없이 공개 공고 내용을 붙여 넣고, 공고명·지원대상·지원내용·마감일·원문 링크를 일정한 형식으로 정리하는 데 집중하면 됩니다.

이 도구가 잘 작동하면 다음 단계로 기업 매칭이나 안내 기록을 붙이면 돼요.

핵심 첫 과제는 오늘 안에 끝낼 수 있는 크기로 고릅니다. (단, 이번 수업에서는 공통 제시 과제로 진행합니다.)

3.2MVP 범위 정하기

MVP(Minimum Viable Product)는 핵심 행동 하나가 되는 가장 작은 첫 버전입니다.

공통 과제 · 이번 수업에서 함께 만들 웹 서비스

창업 지원사업 레이더

관심 키워드를 등록하면 맞는 지원사업 공고를 알려 주고, 입주기업별 안내와 주간 브리핑까지 만드는 웹 서비스입니다.

※ 공통 과제이지만, 맡은 업무에 맞게 사용자·데이터·기능을 바꿔서 만들어도 됩니다.

4.3PRD 결과 확인하기

만들어진 PRD.md에서 Codex가 더한 목적·완료 조건·추가로 정할 사항을 확인합니다.

PRD.md 결과 예시창업 지원사업 레이더 — PRD

항목내용
1. 목적 AI관심 키워드에 맞는 지원사업 공고를 모아 보고, 입주기업별 안내와 주간 브리핑을 준비하는 반복 작업을 줄인다. 가상 데이터로 업무 흐름을 검증한다.
2. 사용자입주기업에 지원사업을 안내하는 센터 담당자
3. 해결할 문제여러 사이트에서 매주 공고를 직접 찾아야 하며, 공고를 놓치거나 기업별 안내 기록을 정리하기 어렵다.
4. 핵심 행동관심 키워드에 맞는 공고를 확인하고, 적합한 입주기업에 보낼 안내 문구를 준비한다.
5. 화면 ① 레이더키워드 등록·삭제, 일치 공고 목록, 접수 기간·D-day·스크랩 여부 표시. 공고 상세와 주간 브리핑으로 이동한다. 초안 기준: 공고명·키워드·지원 내용에 등록 키워드가 하나 이상 포함되면 표시한다.
6. 화면 ② 공고 상세공고 정보, 추천 기업과 매칭 이유, 기업별 안내 문구 생성·복사, 스크랩, 안내 여부 기록. 초안 기준: 지역·창업 단계·신청 대상 조건을 충족한 기업 중 분야 또는 관심 키워드가 일치하면 추천한다. 정보가 부족하면 ‘확인 필요’로 표시한다.
7. 화면 ③ 주간 브리핑키워드에 맞는 접수 중 공고와 이번 주 마감 공고를 요약하고, 스크랩 공고를 별도로 표시한다. 공고명·지원 대상·지원 내용·마감일을 한 번에 복사한다. 초안 기준: 월요일~일요일을 한 주로 본다.
8. 공고 데이터가상 공고 30건 CSV. 공고 ID, 공고명, 주관기관, 지원 분야, 지역, 창업 단계, 신청 대상, 접수 시작일·마감일, 키워드, 지원 내용
9. 입주기업 데이터가상 입주기업 10곳 CSV. 기업 ID, 기업명, 분야, 창업 단계, 지역, 관심 키워드. 실제 기업 정보·개인정보는 사용하지 않는다.
10. 안내·관리 데이터공고별 스크랩 여부, 공고·기업 조합별 안내 문구와 안내 여부. 문구 복사만으로 안내 완료 처리하지 않고 담당자가 직접 표시한다. 초안 기준: 키워드·스크랩·안내 상태는 현재 브라우저에 저장하고 새로고침 후 유지한다.
11. 마감일·공휴일 원칙한국 날짜 기준으로 D-day를 표시한다. 당일은 ‘D-day’, 이후는 ‘마감’으로 표시한다. 공식 접수 마감일은 공휴일 때문에 변경하지 않는다. 초안 기준: 내부 준비 마감은 접수 마감일 이전 2영업일이며, 토·일요일과 공휴일 파일의 날짜를 제외한다.
12. 데이터·연동 범위가상 공고·가상 기업 CSV와 공휴일 파일로 기본 실행한다. K-Startup API는 선택 사항이며 완료 조건에서 제외한다. 실시간 수집·새 공고 알림은 이번 MVP에 포함하지 않는다.
13. 완료 조건 AI① API 없이 가상 데이터 전체를 읽는다.
② 키워드 추가·삭제에 따라 공고 목록이 바뀐다.
③ 매칭 이유와 복사 가능한 안내 문구를 확인한다.
④ 스크랩·기업별 안내 상태가 새로고침 후 유지된다.
⑤ D-day와 주말·공휴일을 반영한 내부 준비 마감이 정확하다.
⑥ 주간 브리핑을 한 번에 복사한다.
⑦ 전체 흐름이 3개 화면 이내이며, 검색 결과가 없거나 데이터가 누락되면 쉬운 안내 문구를 표시한다.
14. 이번에 안 할 것로그인, 자동 메일 발송, 자동 신청, 실제 기업 정보 업로드, 다중 사용자 공유·동기화, 모든 공고 사이트 자동 수집. 기업 추천으로 신청 자격을 확정하지 않는다.
15. 추가로 정할 사항 AI‘초안 기준’으로 표시한 검색·매칭 방식, 브리핑 대상, 저장 방식, 내부 준비 기한은 구현 전에 조정할 수 있다. 공휴일 파일의 적용 연도·출처·갱신 담당을 정해야 한다. 신규 공고 중심 브리핑에는 ‘게시일’ 데이터가 추가로 필요하다.

AI 표시는 3.1·3.2에 없던 내용을 Codex가 채워 더한 항목입니다.

[참고] 실무 PRD로 업데이트한 예시

실무 PRD는 기술 스택·디자인 시스템·비기능 요구사항까지 담아, 기획·디자인·개발이 같은 문서를 기준으로 일합니다.

1. 개요
목적·사용자입주기업에 지원사업을 안내하는 센터 담당자가 관심 공고를 한곳에서 확인하고, 적합한 기업에 보낼 안내를 준비하며 안내 이력을 관리한다. 매주 여러 사이트를 직접 검색하고 안내 내역을 따로 정리하는 부담을 줄인다.
MVP 목표가상 데이터로 공고 탐색 → 기업 매칭 확인 → 안내 문구 준비 → 주간 브리핑 흐름을 끝까지 수행할 수 있는 화면 3개를 만든다.
성공 지표 실무 추가도입 전후로 매주 공고 확인·안내 정리에 드는 시간과 안내 누락 건수를 비교한다.
2. 범위
우선순위 실무 추가필수: 키워드 검색, 공고 상세·기업 매칭, 안내 문구·안내 완료 기록, 주간 브리핑
선택: K-Startup API 연결, 브리핑 인쇄·저장
이번에 하지 않을 것로그인, 자동 메일 발송, 자동 신청, 실제 기업 정보 업로드. K-Startup API 연결은 선택 사항이며 연결 없이도 MVP 완료 조건을 충족해야 한다.
3. 화면·사용자 흐름
화면 1: 레이더관심 키워드를 등록·삭제하고 공고 목록을 확인한다. 공고명·주관기관·지원 분야·지역·접수 마감일·D-day를 표시한다. 키워드로 공고를 찾고, 스크랩하거나 상세 화면으로 이동한다. 키워드가 없으면 전체 공고, 검색 결과가 없으면 안내 메시지를 표시한다.
화면 2: 공고 상세공고의 전체 정보를 보여 주고, 입주기업별 매칭 결과와 이유를 표시한다. 담당자가 안내할 기업을 선택하면 기업명·공고명·지원 내용·접수 기간을 담은 안내 문구를 만들고 수정·복사할 수 있다. 담당자가 실제 안내 후 직접 ‘안내 완료’를 기록한다. 복사만으로 완료 처리하지 않는다.
화면 3: 주간 브리핑해당 주의 스크랩 공고와 안내 완료 내역을 요약한다. 공고별 마감일, 안내 대상 기업, 안내 여부를 함께 확인하고 상세 화면으로 이동한다. 가정: 월요일~일요일을 한 주로 하며, 그 주에 스크랩하거나 안내한 내역을 기준으로 집계한다.
4. 데이터
공고 데이터가상 공고 30건(CSV): 공고명, 주관기관, 지원 분야, 지역, 창업 단계, 신청 대상, 접수 기간(시작일·마감일), 키워드, 지원 내용. 공고마다 고유 번호를 둔다.
입주기업 데이터가상 입주기업 10곳(CSV): 기업명, 분야, 창업 단계, 지역, 관심 키워드. 기업마다 고유 번호를 두며 실제 기업 정보는 사용하지 않는다.
안내·관리 데이터공고별 스크랩 여부·스크랩 시각, 공고와 기업의 조합별 안내 문구·안내 여부·안내 완료 시각을 저장한다. 키워드와 관리 기록은 새로고침 후에도 유지한다. 가정: 로그인 없이 같은 브라우저에서만 보관한다.
5. 업무 규칙
검색·매칭 규칙초기 가정: 등록 키워드 중 하나라도 공고명·키워드·지원 내용에 포함되면 검색 결과에 표시한다. 기업 매칭은 분야·창업 단계·지역·관심 키워드의 일치 항목을 이유와 함께 보여 주며, 하나 이상 일치한 기업을 후보로 표시한다. 후보 표시는 신청 자격 확정을 뜻하지 않으며 신청 대상은 담당자가 검토한다.
날짜·공휴일 규칙한국 날짜 기준으로 D-day = 접수 마감일 − 오늘을 달력 날짜로 계산한다. 당일은 D-day, 지난 공고는 ‘마감’으로 표시한다. 공휴일 때문에 접수 마감일을 바꾸지 않는다. 내부 준비 마감은 공휴일 파일과 주말을 제외한 영업일로 계산한다. 준비에 필요한 영업일 수는 확인 필요이며, 정해지기 전에는 날짜를 임의로 표시하지 않는다.
6. 기술 스택 실무 추가
화면HTML·CSS·JavaScript만 사용하고, 설치 없이 index.html을 열면 실행된다.
데이터가상 공고·입주기업 CSV와 공휴일 파일을 data/ 폴더에 두고 화면에서 읽는다.
저장키워드·스크랩·안내 기록은 브라우저 로컬 스토리지(LocalStorage)에 저장하고, 주간 브리핑은 JSON 파일로 내보내기·가져오기 한다.
API 연결(선택)Node.js 서버 파일(server.js)이 K-Startup API를 대신 호출하고, 인증키는 .env 파일에만 둔다.
파일 구조index.html · css/style.css · js/script.js · data/ · assets/ · PRD.md · AGENTS.md · DESIGN.md · CHANGELOG.md
7. 디자인 시스템 실무 추가
색기본 초록(레이더·주요 버튼), 마감 임박 빨강, 곧 마감 황토, 연한 회녹색 배경, 진한 글자색 5가지로 제한한다.
글꼴Pretendard(없으면 맑은 고딕), 본문 15px 안팎, 숫자 요약은 크게 표시한다.
컴포넌트상단 탭(레이더·주간 브리핑), 요약 숫자 카드, 공고 카드, D-day 배지, 키워드 칩, 상세 패널, 복사 버튼, 토스트 알림
레이아웃PC는 왼쪽 조건·오른쪽 공고 목록 2열, 휴대폰은 1열로 쌓는다.
관리색·글꼴·컴포넌트 규칙은 DESIGN.md에 따로 적어 두고 화면을 고칠 때 함께 맞춘다.
8. 비기능 요구사항 실무 추가
보안·개인정보개인정보·실제 기업 정보를 쓰지 않고, 인증키는 .env에만 두며 공유·업로드하지 않는다.
화면·브라우저PC와 휴대폰 화면에서 깨지지 않고, 크롬·엣지 최신 버전에서 동작한다.
접근성주요 버튼은 키보드로도 쓸 수 있고, 색만으로 상태를 구분하지 않는다(D-day 글자 함께 표시).
9. 완료 조건
완료 조건① 가상 공고 30건·기업 10곳·공휴일 파일을 읽는다.
② 키워드 등록·삭제가 목록에 반영된다.
③ 목록에서 상세로 이동해 기업 후보와 매칭 이유를 확인한다.
④ 안내 문구를 수정·복사하고 기업별 안내 완료를 기록한다.
⑤ 주간 브리핑에 스크랩·안내 기록이 정확히 반영된다.
⑥ 새로고침 후 키워드·스크랩·안내 기록이 유지된다.
⑦ 마감 당일·지난 공고·주말·공휴일 사례에서 날짜 규칙이 맞게 동작한다.
10. 가정·확인 필요
확인 필요내부 준비에 필요한 영업일 수와 기준 시점, 기업 매칭 규칙, 주간 브리핑의 집계 기준, 같은 브라우저에만 저장하는 방식의 적합성을 확정한다. 가상 CSV와 공휴일 파일의 열 이름·날짜 형식·적용 연도·지역을 구현 전에 정한다.
근거사용자가 제공한 [정리 결과]와 [MVP 범위]. 추가한 운영 규칙은 ‘가정’으로 구분했으며, 구현 시 확인 후 조정한다.

5.1PRD를 Codex에 전달하기

PRD.md를 Codex에 읽히고 작업 순서를 받습니다.

  • 폴더에 PRD.md와 AGENTS.md가 있는지 확인합니다
  • 프롬프트를 보내고, 받은 요약과 작업 순서를 읽어 봅니다
  • AI가 물어본 정해야 할 것을 확인해 둡니다
나는 코딩을 모르는 초보자야. 이 폴더의 PRD.md를 먼저 읽어줘.
아직 코드는 만들지 말고, 아래 3가지만 쉬운 말로 알려줘.
1. PRD를 읽고 이해한 내용을 3줄로 요약
2. MVP를 만들기 위한 작업 순서(3~5단계, 단계마다 확인할 것 포함)
3. PRD에서 빠졌거나 애매해서 내가 정해야 할 것

아직 만들지는 말아줘. 다음 시간에 이 순서대로 한 단계씩 진행할 거야.
[참고] 창업 지원사업 레이더 예시
1. 이해한 내용 — 3줄 요약

센터 담당자가 관심 키워드로 지원사업 공고를 찾는 서비스입니다.
공고에 맞는 입주기업을 확인하고, 안내 문구와 안내 기록을 관리합니다.
가상 공고 30건·기업 10곳으로 레이더 → 공고 상세 → 주간 브리핑의 3개 화면을 만듭니다.

2. MVP 작업 순서
단계할 일단계가 끝나면 확인할 것
1아래의 애매한 규칙을 정하고 가상 데이터 준비공고 30건·기업 10곳이 있고, 날짜와 분류 기준이 같은가?
2화면 3개와 화면 이동 만들기index.html을 더블클릭해 열고, 세 화면을 오갈 수 있는가?
3레이더의 키워드 검색·스크랩·마감일 표시 만들기키워드에 맞는 공고가 나오고, 마감일 계산이 맞는가?
4기업 매칭·안내 문구·안내 완료 기록 만들기추천 이유를 확인하고 문구를 수정·복사하며 기업별 안내 여부를 기록할 수 있는가?
5주간 브리핑과 기록 저장 연결 후 전체 확인주간 내역이 정확하고, 새로고침해도 기록이 남는가?
3. 직접 정해야 할 것
정할 것선택 예시·추천
내부 준비 마감접수 마감일에서 3영업일 전처럼 며칠 앞당길지 정하기
기업 추천 기준현재는 조건 하나만 맞아도 후보입니다. 지역·창업 단계가 맞는 기업을 먼저 추천할지 정하기
주간 브리핑 기준PRD의 가정인 월~일에 스크랩하거나 안내한 내역으로 할지 정하기
기록 저장 범위첫 버전은 같은 컴퓨터·같은 브라우저에서만 저장해도 되는지 정하기
공휴일 범위대한민국 공휴일, 어느 연도를 사용할지 정하기
가상 데이터 여는 방법더블클릭 실행 조건에 맞춰, 시작할 때 CSV 파일을 직접 선택하는 방식이어도 되는지 정하기

CSV의 열 이름과 날짜 표기 같은 세부 형식은 제가 통일해서 제안할 수 있습니다.

이번에는 파일을 수정하거나 코드를 만들지 않았습니다.

5.2정할 것에 답하고 PRD 업데이트하기

5.1에서 받은 정해야 할 것에 답해 PRD.md를 고칩니다.

  • 5.1 답변의 직접 정해야 할 것을 확인합니다
  • {정할 것}마다 {내 답}을 채워 보냅니다
  • PRD.md에서 확인 필요 항목이 줄었는지 봅니다
PRD.md에서 아래 정할 것을 내 답대로 고쳐줘.

{정할 것 1}: {내 답}
{정할 것 2}: {내 답}
{정할 것 3}: {내 답}

고친 뒤 무엇이 바뀌었는지 짧게 알려주고, 아직 정해야 할 것이 남았으면 알려줘.
[참고] 창업 지원사업 레이더 예시
PRD.md에서 아래 정할 것을 내 답대로 고쳐줘.

내부 준비 마감: 접수 마감일에서 3영업일 전으로 해줘.
기업 추천 기준: 지역·창업 단계가 맞는 기업을 먼저 추천하고, 분야·관심 키워드가 맞는 순으로 보여 줘.
주간 브리핑 기준: 월~일에 스크랩하거나 안내한 내역으로 해줘.
기록 저장 범위: 첫 버전은 같은 컴퓨터·같은 브라우저에서만 저장해도 돼.
공휴일 범위: 대한민국 공휴일, 2026~2027년을 써줘.
가상 데이터 여는 방법: CSV는 미리 data/data.js로 바꿔 두고, 더블클릭으로 바로 열리게 해줘.

고친 뒤 무엇이 바뀌었는지 짧게 알려주고, 아직 정해야 할 것이 남았으면 알려줘.
