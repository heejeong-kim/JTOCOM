1.1준비

  • Codex에서 새 채팅을 열고, 프로젝트 선택에서 support-guide 폴더를 고릅니다
  • 폴더에 AGENTS.md가 있는지 확인합니다

1.2PRD로 첫 화면 만들기

  1. ① 첫 화면 만들기

    이 폴더의 PRD.md를 읽고, PRD에 적힌 화면 중 첫 화면(공고 목록) 하나만 먼저 만들어줘.
- 아직 진짜 데이터가 없으니 가상의 지원사업 공고 5개를 넣어줘.
- 휴대폰 화면에서도 깨지지 않게 해줘.

  2. ② 컴포넌트 이름으로 고쳐 보기

    "헤더(Header)에 서비스 이름과 오늘 날짜를 넣어줘""카드(Card)를 한 줄에 2개씩 보여 줘""지원 분야를 고르는 탭(Tab)을 목록 위에 넣어줘""카드에 마감 D-day를 배지(Badge)로 보여 줘"
    지금 화면에서 {고칠 곳의 컴포넌트 이름}을(를) 고쳐줘.
바꾸고 싶은 점: {어떻게 바뀌면 좋을지}

  3. ③ 첫 이력 남기기

    첫 화면을 만든 것을 CHANGELOG.md 맨 위에 한 줄 남겨줘. CHANGELOG.md가 없으면 새로 만들어줘.
핵심 PRD를 기준으로 첫 화면을 만들고, 세부는 컴포넌트 이름으로 고쳐 달라고 말합니다.

2.2함께 해 보기

  1. ① CSV로 공고 목록 넣기

    • startup-programs.csv 가상 공고 30건
    • startups.csv 가상 입주기업 10곳

    내려받은 파일을 프로젝트의 data 폴더에 넣고 요청합니다.

    data 폴더에 startup-programs.csv(공고)와 startups.csv(입주기업) 파일을 넣었어.
이 파일의 공고 30건을 지금 화면의 예시 데이터 대신 보여 줘.
1. 먼저 두 파일에 어떤 열이 있는지, 몇 줄인지 알려줘.
2. 데이터를 data/data.js 파일로 바꿔서 연결해줘.
3. 지원 분야와 지역을 고르면 맞는 공고만 보이게 해줘.
4. 원본 CSV 파일은 바꾸지 말아줘.

  2. ② 로컬 스토리지에 관심 키워드 남기기

    화면 왼쪽에 '관심 키워드'를 넣는 칸과 추가 버튼을 만들어줘.
- 키워드를 추가하면 공고명이나 키워드 칸에 그 말이 들어간 공고만 보여 주고, 맞은 키워드는 색으로 표시해줘.
- 등록한 키워드와 별(★)로 스크랩한 공고는 새로고침하거나 창을 닫았다 열어도 남게 로컬 스토리지(LocalStorage)에 저장해줘.
- 저장된 값을 개발자 도구 어디에서 볼 수 있는지 쉬운 말로 알려줘.

  3. ③ JSON으로 브리핑 파일 주고받기

    동료에게 넘길 수 있게 '브리핑 파일 내보내기'와 '브리핑 파일 불러오기' 버튼을 만들어줘.
- 내보내기를 누르면 관심 키워드, 스크랩한 공고, 안내한 입주기업 기록을 radar-briefing.json 파일로 내려받게 해줘.
- 불러오기로 그 파일을 고르면 같은 내용이 화면에 보이게 해줘.
- JSON이 무엇인지 3줄로, 공고 하나가 JSON에서 어떻게 생겼는지 예를 들어 쉬운 말로 알려줘.

  4. ④ 공휴일 파일로 마감 근무일 계산하기

    • holidays.csv 공휴일 2026.12~2027.3

    내려받은 파일을 data 폴더에 넣고 요청합니다. 우주항공청 월력요항 기준 공휴일입니다.

    data 폴더에 holidays.csv(공휴일 목록)를 넣었어.
1. 공고 카드마다 접수 마감까지 남은 근무일을 '근무일 5일'처럼 보여 줘. 주말과 이 파일의 공휴일은 빼 줘.
2. 마감일이 주말이나 공휴일이면 그 전 근무일을 '준비 마감'으로 보여 줘.
3. 원본 CSV 파일은 바꾸지 말아줘.
    옵션 · K-Startup 공고 API로 실제 공고 받아 오기
    공공데이터포털의 'K-Startup 사업공고' API로 지금 모집 중인 지원사업 공고를 받아 와서 레이더에 보여 주고 싶어.
인증키는 내가 .env 파일에 직접 넣을게.

1. 시작하기 전에 필요한 파일과 내가 직접 할 일을 먼저 알려줘.
2. 인증키가 화면에 드러나지 않도록, 이 컴퓨터에서 대신 불러 주는 작은 서버(server.js)로 만들어줘.
3. 받아 온 공고를 가상 공고 대신 보여 주고, 실패하면 가상 공고로 보여 줘.
4. 실패하면 오류 내용을 쉬운 말로 알려줘.
    • 인증키는 .env 파일에만 두고, 화면·채팅·공유 파일에 붙여 넣지 않습니다
    • 브리핑 파일이나 폴더를 줄 때는 .env 파일을 빼고 줍니다
  • 단계(①~④)가 끝날 때마다 "CHANGELOG.md에 이력을 한 줄 남겨줘"라고 요청합니다
핵심 CSV로 넣고, 로컬 스토리지에 남기고, JSON으로 넘기고, 공휴일 파일로 마감 근무일을 계산합니다.

3.2내 과제에 연결하기

이 폴더의 PRD.md를 읽고, 내 과제의 첫 화면을 만들어줘. (PRD.md가 없다면 먼저 알려줘)
그다음 내 데이터를 연결하고 싶어.

내 데이터: {파일 이름 또는 쓰고 싶은 공공데이터 이름}
필요한 것: {예: 표로 보기, 즐겨찾기 저장, 최신 데이터 받아 오기}

CSV, JSON, 로컬 스토리지, 공공데이터 API 중 무엇이 필요한지 먼저 추천해 주고, 내가 고르면 하나씩 연결해줘.
원본 파일은 바꾸지 말아줘.
다른 방법 · 2교시에 뜯어본 서비스를 참고해 시작하고 싶을 때 열기 
내가 참고한 서비스를 바탕으로, 비슷한 문제를 해결하는 나만의 웹 서비스 첫 화면을 만들고 싶어.
참고 서비스의 이름·문구·로고·브랜드 디자인은 그대로 베끼지 말고, 사용자에게 필요한 기능과 유저 플로우만 참고해줘.

[참고한 서비스]
서비스: {서비스명 또는 URL}
분석 결과: {뜯어보기에서 받은 분석 결과를 그대로 붙여 넣기}

[내가 만들 서비스]
서비스 이름: {서비스 이름}
사용자: {누가 사용하는지}
해결할 불편: {어떤 문제를 줄일지}
사용자가 끝내려는 일: {핵심 행동 하나}

[참고 서비스에서 가져올 것]
레이아웃·컴포넌트: {필요한 화면 영역과 컴포넌트}
유저 플로우: {화면 → 화면 순서}
데이터 항목: {화면에 표시할 정보}

[만들기 조건]
- 만들기 전에 어떤 화면을 어떤 순서로 만들지 3줄로 먼저 알려주고 바로 만들어줘.
- 브라우저에서 바로 열리는 웹(HTML·CSS·JavaScript)으로 만들고, PC와 휴대폰 화면에서 모두 잘 보이게 해줘.
- 핵심 행동 하나가 작동하는 첫 결과물에 집중해줘.
- 실제 개인정보 대신 가상의 예시 데이터 5~10개를 넣어줘.
- 로그인과 실제 데이터 저장은 하지 말고, 우선 화면 안의 예시 데이터로 동작하게 해줘.
- 버튼과 입력 기능을 직접 확인하고, 작동하지 않는 부분은 고쳐줘.
- 마지막에 파일을 여는 방법, 만든 기능, 다음에 추가하면 좋을 기능 1가지를 쉬운 말로 알려줘.

3.3내 데이터가 없다면 · 레이더에 우리 입주기업 넣어 보기

실제 기업명·연락처는 빼고 가상 이름으로 입주기업 3곳의 분야와 관심 키워드만 넣어 봅니다.

레이더에 입주기업 3곳을 추가해줘.
기업 1: {가상 기업명 / 분야 / 창업 단계 / 지역 / 관심 키워드(; 로 구분)}
기업 2: {가상 기업명 / 분야 / 창업 단계 / 지역 / 관심 키워드}
기업 3: {가상 기업명 / 분야 / 창업 단계 / 지역 / 관심 키워드}
data/startups.csv와 data/data.js에 함께 넣고, 이 기업들에 맞는 공고가 몇 건인지 알려줘.
참고 · 공공데이터 파일로 연습하기

내려받은 파일은 district.csv, senior-center.xlsx처럼 짧은 영문 이름으로 바꿔 data 폴더에 넣습니다.

  • 행정구역 현황.csv 한글 깨짐 · 숫자에 쉼표
  • 경로당 현황.xlsx 제목 줄이 여러 줄
data 폴더에 공공데이터 파일 {파일 이름}을(를) 넣었어.
1. 파일에서 손봐야 할 점(한글 깨짐, 여러 줄 제목, 숫자 속 쉼표 등)을 먼저 알려줘.
2. 정리한 데이터를 data/data.js로 만들어줘. 원본 파일은 그대로 둬.
3. 위에는 핵심 숫자 카드 3개, 아래에는 표를 보여 줘.
