바이브코딩이란

1.1개념

만들고 싶은 것을 말로 설명하면 AI가 코드를 작성하는 개발 방식으로, 사람은 원하는 것을 말하고 결과를 확인해 고쳐 달라고 요청합니다.

1.2기존 개발과의 차이

기존 개발완성까지 며칠 ~ 몇 주
  1. 기획 담당자아이디어
  2. 요청서 작성기능 정리
  3. 개발 대기일정 조율
  4. 개발자 코딩직접 작성
  5. 수정 요청다시 대기
바이브코딩첫 결과물까지 몇 분 ~ 몇 시간
  1. 나 (실무자)아이디어
  2. 말로 요청프롬프트
  3. AI가 코드 작성몇 초~몇 분
  4. 바로 확인·수정반복

1.3발전 히스토리

  1. 2021~코드 자동완성

    개발자가 코드를 쓰면 AI가 다음 줄을 제안. 여전히 개발자 중심

  2. 2022 말~대화형 코드 생성

    ChatGPT 같은 챗봇에 말로 물어 코드를 받아 복사해 붙여 씁니다

  3. 2023~2024AI 코드 에디터

    편집기 안에서 AI가 여러 파일을 한 번에 읽고 고칩니다

  4. 2025.02'바이브코딩' 용어 등장

    안드레이 카파시가 "코드의 존재조차 잊는" 개발 방식을 바이브코딩이라 부릅니다. 같은 해 11월 콜린스 사전 '올해의 단어' 선정

  5. 2025~AI 코딩 에이전트

    Codex 등 에이전트가 계획 → 구현 → 테스트까지 스스로 진행, 사람은 지시·검토

  6. 2026 현재현업·공공으로 확산

    개발자가 아닌 실무자가 업무 도구와 서비스를 직접 만드는 단계

핵심 바이브코딩에서는 코딩 지식만큼 무엇을 원하는지 정확히 말하는 힘이 중요합니다.

2.1웹과 앱

웹은 브라우저에서 주소(URL)로 여는 서비스, 앱은 휴대폰에 설치해서 쓰는 서비스입니다.

브라우저 · 오늘 만드는 것

웹 · Web

크롬·엣지 같은 브라우저에서 주소로 바로 여는 서비스

예시
기관 홈페이지, 지원사업 신청, 평가점수 집계 도구
특징
설치 없이 링크만 보내면 PC·휴대폰 어디서나 열립니다
AI 요청
"PC와 휴대폰 브라우저에서 모두 잘 보이는 웹으로 만들어줘"
설치

앱 · App

앱스토어·플레이스토어에서 내려받아 설치하는 서비스

예시
은행 앱, 메신저 앱, 저 내려요
특징
알림·카메라 등 휴대폰 기능을 쓰기 쉽지만, 스토어 심사와 설치가 필요합니다
AI 요청
"앱처럼 휴대폰 화면에 맞춘 웹으로 먼저 만들어줘"

2.4만들고, 고치고, 공개하기

오류 메시지실행이 안 될 때 뜨는 빨간 안내 글. 그대로 복사해 AI에게 전달
개발자 도구 · 콘솔브라우저에서 F12로 여는 점검 창. 숨은 오류가 여기 보입니다
버전 · 체크포인트잘 될 때 저장해 두는 지점. 망가지면 이 지점으로 되돌립니다
로컬 · Local내 컴퓨터에서만 열리는 상태. 다른 사람은 못 봅니다
배포 · Deploy만든 서비스를 인터넷에 올려 누구나 쓸 수 있게 하는 일
URL서비스에 접속하는 인터넷 주소
도메인 · DomainURL 속 사이트 이름. 예: example.com
나는 코딩을 전혀 모르는 완전 초보자야. 만들던 화면에서 아래 빨간 오류 메시지가 떴어.
1. 이 오류가 무슨 뜻인지 전문 용어 없이 일상 비유로 한두 줄로 설명해줘. 꼭 써야 하는 용어가 있으면 바로 옆에 쉬운 뜻을 붙여줘.
2. 왜 이런 오류가 생겼는지 원인을 쉬운 말로 알려줘. 원인이 여러 가지일 수 있으면 가능성이 높은 순서로 알려주고, 내가 무엇을 확인하면 되는지도 알려줘.
3. 고치기 전에 무엇을 어떻게 바꿀지 먼저 말해주고, 내가 "좋아"라고 하면 그때 고쳐줘.
4. 고친 뒤에 내가 화면에서 무엇을 눌러 보면 제대로 됐는지 확인할 수 있는지 알려줘.

움직임 넣기

화면에 움직임(모션)을 넣어줘. 나는 모션 용어를 잘 모르는 초보자야.
버튼에 마우스를 올리면 0.2초 동안 부드럽게 색이 바뀌고, 메뉴와 팝업은 빨리 열려서 천천히 멈추게 해줘.
움직임은 과하지 않게 하고, 휴대폰이나 컴퓨터에서 '움직임 줄이기'를 켠 사람에게는 움직이지 않게 해줘.
핵심 화면을 만들기 전에 디자인 규칙부터 정해 두면 여러 번 고쳐도 화면의 느낌을 비슷하게 유지하기 쉽습니다.

오늘의 핵심

  • 바이브코딩 = 말로 지시하고, 확인하고, 고쳐 가며 만드는 방식
  • 서비스는 화면 · 서버 · 데이터로 이루어지고, API로 연결되고, 배포로 공유됩니다
  • 잘 만드는 비결은 작게, 정확하게, 확인하며 요청하는 것
