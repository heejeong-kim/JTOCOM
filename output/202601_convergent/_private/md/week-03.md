# 🎙️ 1. 서사의 패러다임 변화: 보는 이야기에서 '작동하는' 이야기로
### 1-1. 선형적 서사(Linear) vs 인터랙티브 서사(Interactive)
기존의 동화가 작가가 정해놓은 '하나의 길'을 따라가는 기차 여행이라면(2주차 배운 일반 콘텐츠), 인터랙티브 동화는 사용자가 직접 핸들을 잡고 운전하는 자율주행 여행(2주차 배운 융합 콘텐츠)
<table header-row="true">
<tr><td>구분</td><td>선형적 서사 (전통적 매체)</td><td>인터랙티브 서사 (융합 콘텐츠)</td></tr>
<tr><td>**핵심 성격**</td><td>**고정성**: 변하지 않는 결과</td><td>**가변성**: 선택에 따른 경로 변화</td></tr>
<tr><td>**구조**</td><td>단일 구조 (시작 → 끝)</td><td>분기 구조 (시작 → 선택 → 다중 결말)</td></tr>
<tr><td>**사용자 역할**</td><td>관람자 (Viewer): 수동적 수용</td><td>플레이어 (Player): 능동적 개입 및 결정</td></tr>
<tr><td>**기술의 역할**</td><td>영상/텍스트 재생 수단</td><td>**로직과 데이터의 연산 엔진**</td></tr>
</table>

### 1-2. 인터랙티브 서사의 3대 핵심 요소
**1) 사건 (Event): 이야기의 최소 단위**
사건은 스토리가 진행되는 과정에서 일어나는 모든 개별적인 장면을 말함. 융합 콘텐츠에서는 이 사건을 '모듈'처럼 관리함
- 고정된 전체 줄거리가 아니라, 하나하나 떼어낼 수 있는 에피소드 조각임
- 사건이 모여서 하나의 경로를 만듦. 기획자는 이 사건들을 어떤 순서로 배치할지 결정함
- **예시**: 콩쥐가 마을 잔치 소식을 듣는 장면, 독에 물을 채우려고 시도하는 장면 등
---
**2) 선택지 (Choice): 사용자가 개입하는 인터페이스**
선택지는 사용자가 서사의 방향을 결정할 수 있도록 기획자가 제공하는 '갈림길'임. 기술적으로는 '입력값'을 받는 단계임
- 주인공의 운명을 바꿀 수 있는 결정적인 순간을 사용자에게 넘겨주는 것임
- 단순히 버튼을 누르는 재미가 아니라, '내가 이 이야기를 만들고 있다'는 효능감을 줌
- **선택의 종류**:
  - **직접적 선택**: "왼쪽으로 갈까? 오른쪽으로 갈까?" (버튼 클릭)
  - **간접적 선택**: 사용자가 특정 장소에 오래 머물거나, 특정 아이템을 줍는 행위 자체가 선택이 됨
---
**3) 결과 (Consequence): 데이터가 반영된 피드백**
결과는 사용자의 선택이 스토리에 어떤 변화를 주었는지 보여주는 '출력값'임. 가장 중요한 건 '데이터의 변화'임
- 사용자의 선택이 단순히 다음 장면을 보여주는 데서 끝나지 않고, 캐릭터의 수치(상태값)를 실제로 바꿔야 함
- 로직의 작동:
  - 단기 결과: 즉각적인 대사의 변화나 연출의 차이 (예: 칭찬을 듣거나 꾸중을 들음)
  - 장기 결과: 누적된 데이터가 나중에 엔딩을 바꿈 (예: 착한 일을 많이 해서 `Karma` 수치가 높으면 나중에 조력자가 나타남)
---
> ✅ [실습] - **생각해보기**
  - 최근에 본 영상 중 '결말이 마음에 안 들어서 내가 바꾸고 싶다'고 생각한 적이 있는가
  - 만약 <토끼와 거북이>에서 토끼가 잠들지 않는 선택을 한다면, 기획자는 어떤 '기술적 장치'로 거북이에게 승리 가능성을 줘야 할까

# 🎙️ 2. 인터랙티브 서사의 3대 설계 구조
콘텐츠의 목적과 제작 예산에 따라 기획자는 아래 세 가지 구조 중 하나를 선택하거나 혼합하여 설계함
### 2-1. 단순 분기 구조 (Simple Branching)
- 선택 즉시 경로가 완전히 갈라짐. 사용자에게 높은 자유도를 주지만, 경로가 늘어날수록 제작 분량이 기하급수적으로 폭주
- **예시**: 왼쪽 문(보물 창고 엔딩) vs 오른쪽 문(함정 엔딩)
---
### 2-2. 수렴 구조 (Convergence / Diamond Structure)
- 중간에 길이 갈라지더라도 결국 '핵심 사건'에서 다시 만남. 제작 효율이 가장 높으며 서사의 일관성을 유지하기 유리함
- **예시**: 아침으로 빵을 먹든 밥을 먹든, 결국 8시에 학교에 도착해 선생님을 만나는 사건
---
### 2-3. 루프 구조 (Loop)
- 특정 조건을 만족하지 못하면 다시 이전 시점으로 되돌림. 교육용 콘텐츠나 고난도 퍼즐 요소에 자주 사용됨
- **예시**: 비밀번호를 맞힐 때까지 계속 입력창이 뜨는 구조
> ✅ [실습] - **생각해보기**
  - 기획자 입장에서 제작비를 아끼면서 사용자에게 '내가 선택하고 있다'는 느낌을 주기에 가장 적합한 구조는 무엇일까
  - 유튜브의 '다음 영상 추천'은 위의 세 구조 중 어디에 가까울까, 혹은 새로운 구조일까
---
# 🎙️ 3. 캐릭터의 데이터화: 감정을 수치로 변환하기
융합 콘텐츠에서 캐릭터는 '그림'이 아니라 '상태값(Status)의 집합체'임. 시스템이 캐릭터를 인식할 수 있도록 숫자로 바꿔주는 과정이 필수적임
### 3-1. 변수의 종류와 역할
**1) 능력치 (Stats - Integer)**: 수치로 표현되는 역량
  - 예: `intelligence = 50`, `energy = 100`
  - 로직: "지능 수치가 80 이상인 플레이어에게만 '암호 해독' 버튼을 노출함"
**2) 인벤토리 (Inventory - Array)**: 보유한 아이템 리스트
  - 예: `item_list = ["황금열쇠", "지도"]`
  - 로직: "인벤토리에 '황금열쇠'가 있어야만 성문을 열 수 있음"
**3) 상태 플래그 (Status Flags - Boolean)**: 사건 발생 여부 (참/거짓)
  - 예: `is_met_king = True` (왕을 만난 적이 있음)
  - 로직: "왕을 만난 적이 있다면 대사가 친근하게 나오고, 없다면 경계하며 나옴"
> ✅ [실습] - **생각해보기**
  - 공포 영화의 주인공 캐릭터를 데이터화한다면, 어떤 변수가 가장 중요할까 (예: 공포 수치, 심박수, 손전등 배터리 잔량 등)
  - '주인공의 용기'를 1~100 사이의 숫자로 정의한다면, 어떤 행동을 했을 때 이 수치를 올려줘야 할까
---
# 🎙️ 4. 사용자 경험(UX)과 '가짜 선택지' (Flavor Choice)
모든 선택이 반드시 거창한 엔딩의 변화로 이어져야만 좋은 인터랙티브 콘텐츠일까? 기획자는 때로 기술적 효율성과 사용자의 기분 사이에서 영리한 전략을 짜야 함
### 4-1. 선택의 환상 (Illusion of Choice)
- 실제로는 이야기의 큰 줄기(엔딩)에 영향을 주지 않지만, 사용자에게는 자신이 서사에 개입하고 있다는 느낌을 주는 장치임
- 제작 리소스를 최소화하는 **수렴 구조**를 활용하면서도, 사용자의 몰입도를 극대화할 수 있는 '가성비' 높은 기획 기술
- 예) 콩쥐가 파티장에 갈 때 [분홍색 꽃신]을 신을지 [파란색 꽃신]을 신을지 결정하게 함. 어떤 색을 골라도 보안팀에 쫓기는 결말은 같지만, 사용자는 "내가 고른 신발을 신고 있네?"라며 콘텐츠가 본인에게 맞춰져 있다고 느낌
---
### 4-2. 가짜 선택지(Flavor Choice)의 가치
- **감정적 피드백**: 엔딩은 바뀌지 않더라도 주인공의 말투나 주변 인물의 반응(대사 한 줄)이 달라지는 것만으로도 사용자는 충분한 보상을 받았다고 느낌
- **성격 형성**: "무서워도 참는다" vs "무서워서 소리 지른다" 같은 선택은 결과는 같을지언정, 유저가 정의하는 '나만의 콩쥐'라는 캐릭터성을 만드는 데 기여함
> ✅ [실습] - 생각해보기
  - 사용자에게 '선택의 환상'을 심어주는 것은 기획자의 기만일까, 아니면 기술적 배려일까?

# 🎙️ 5. 로직 설계: 시스템 뒷단의 작동 원리
사용자가 화면에서 [특정 액션] 버튼을 누르는 순간, 보이지 않는 곳에서는 기획자가 미리 설계한 '조건 검사'와 '데이터 업데이트'가 실시간으로 일어남
### 5-1. 조건문 (If-Else): 이야기의 필터
기획자는 모든 사건에 '입장 조건'을 걸 수 있음. 특정 데이터가 충족되지 않으면 해당 시나리오는 실행되지 않음
- "만약(If) 유저가 A를 가지고 있다면 1번 결과를 보여주고, 아니면(Else) 2번 결과를 보여줘"라는 약속임
- **작동**: 시스템은 유저의 인벤토리와 능력치 데이터를 실시간으로 조회하여 다음 장면을 결정함
---
### 5-2. 데이터 업데이트: 기억하는 시스템
인터랙티브 서사에서 시스템은 유저의 모든 과거를 숫자로 기억함
- **개념**: 선택의 결과가 단순히 화면에 보이고 사라지는 것이 아니라, 변수(Variable)의 값을 영구적으로 바꿈
- **효과**: 1막에서의 사소한 선택이 3막의 엔딩을 바꾸는 '나비 효과'를 기술적으로 구현함
---
### 5-3. 실제 로직 설계
복잡한 코딩을 몰라도 기획자는 아래와 같은 논리 구조를 설계할 수 있어야 함
```javascript
# [사건] 데이터 센터 누수 차단 미션 (2099 네오-콩쥐)

IF 사용자의_선택 == "나노봇_호출":
    # 1단계: 아이템 보유 여부 체크
    IF 인벤토리.has("나노_두꺼비"):
        Outcome = "미션 성공"
        Sync_Rate += 10    # 동기화율(기술력) 상승
        Display = "두꺼비 로봇들이 구멍 난 데이터 망을 완벽히 메웁니다"

    # 2단계: 아이템이 없을 경우의 처리
    ELSE:
        Outcome = "미션 실패"
        Integrity -= 5     # 시스템 오염 혹은 주인공의 멘탈 수치 하락
        Display = "도구 없이는 불가능합니다. 시스템이 과열되어 경고음이 울립니다"

# 결과적으로 바뀐 데이터(Sync_Rate, Integrity)는 다음 사건인 '잔칫집 입장'의 난이도를 결정함
```
> ✅ [실습] - 생각해보기
  - 만약 콩쥐가 '나노_두꺼비' 아이템은 없는데, 대신 `Sync_Rate`(동기화율) 수치가 90 이상인 '천재 해커'라면 미션을 성공시키고 싶음. 위 로직을 어떻게 수정하면 좋을까?

# ✏️ [Case Study] Project: NEO-KONGJI : 2099년 디스토피아 배경 재설계
## 1. 서사의 변화: 콩쥐는 왜 더 이상 울지 않는가
기존 동화의 콩쥐는 계모가 시킨 일을 못 해서 울기만 하지만, 융합 콘텐츠(2099)의 콩쥐는 기술을 활용해 상황을 해결하는 '플레이어'로 전환
- 선형적 서사 (원본): 계모가 독에 물 채우라고 함 → 콩쥐가 움 → 두꺼비가 나타나 도와줌 (결과 고정)
- 인터랙티브 서사 (NEO-KONGJI): 데이터 센터 누수 발생 → [사용자의 선택] 직접 해킹할 것인가? 나노봇을 소환할 것인가? → 선택에 따라 콩쥐의 능력이 변하거나 엔딩이 달라짐 (결과 가변)
---
## 2. 인터랙티브 서사의 3대 설계 구조 (Feat. NEO-콩쥐)
기획자는 단순히 재미있는 이야기를 쓰는 것을 넘어, '제작 예산'과 '사용자의 만족도' 사이에서 줄타기를 해야 함. 이때 사용하는 3가지 설계도가 있음
**2-1. 단순 분기 구조 (Simple Branching) - "전부 다 만들어야 하는 노가다 구조"**
사용자가 선택하는 족족 이야기가 완전히 새끼를 치며 뻗어나가는 방식임
- "잔치에 갈래, 안 갈래?"라고 물었을 때, 안 간다고 하면 거기서 바로 끝나는 '정비공 엔딩' 전용 스토리를 따로 다 써야 함
- 사용자는 "와, 내 선택에 따라 세상이 바뀌네?"라고 좋아하지만, 기획자는 선택지가 10개면 10개 분량의 시나리오를 다 써야 하므로 힘든 여정, 보통 '단기 엔딩(Bad Ending)'을 처리할 때 많이 씀
---
**2-2. 수렴 구조 (Convergence / Diamond) - "모든 길은 결국 잔칫집으로"**
사용자가 어떤 선택을 하든, 이야기의 핵심이 되는 중요한 장면(체크포인트)에서 다시 만나게 하는 방식임
- 콩쥐가 [나노봇 두꺼비]를 불러서 독을 고치든, 본인의 [해킹 실력]으로 독을 고치든, 결국은 '메가 코프 파티장(잔칫집)'에 입장하는 장면으로 모임
- 기획자 입장에서 가장 **가성비**가 좋음. 중간에 콩쥐의 대사만 살짝 다르게 연출(예: "두꺼비 덕분에 왔어" vs "내 실력으로 왔지")해주면, 사용자는 자기 선택이 반영되었다고 느끼면서도 기획자는 파티장 이후 스토리를 하나만 써도 됨
---
**2-3. 루프 구조 (Loop) - "성공할 때까지 무한 반복"**
특정 미션을 해결하지 못하면 시간을 되돌리거나 이전 상태로 복구시키는 방식임
- 콩쥐가 데이터 센터 보안망을 해킹해야 하는데 실패했음. 그럼 "게임 오버" 하고 끝내는 게 아니라, "시스템 오류! 다시 시도하시겠습니까?"라며 해킹 시작 전 시점으로 콩쥐를 돌려보냄
- 사용자에게 실패를 만회할 기회를 주고 학습을 시킬 수 있음. 하지만 너무 많이 반복하면 사용자가 짜증을 낼 수 있으므로 적절한 힌트를 주는 설계가 병행되어야 함
---
## 3. 데이터화: 콩쥐의 감정을 숫자로 바꾸기
시스템은 콩쥐가 착한지 나쁜지 모름. 오직 숫자로만 판단함
- 변수 1. 동기화율 : 콩쥐가 기계를 얼마나 잘 다루는지 보여줌. 이게 80 이상이어야 나중에 최종 보스(팥쥐)의 시스템을 강제 종료할 수 있음
- 변수 2. 도덕성 : 나쁜 짓(해킹 등)을 하면 떨어짐. 이게 너무 낮으면 '다크 콩쥐' 엔딩으로 빠짐
- 변수 3. 인벤토리 : `["나노 두꺼비", "홀로그램 꽃신"]`. 꽃신 아이템이 리스트에 있어야만 파티장 입구의 생체 인식기를 통과할 수 있음
- 변수 4. 상태 플래그 : `is_met_fairy = True`. 선녀(해커 리더)를 만났는지 여부를 저장해서 나중에 결정적인 도움을 줄지 말지 결정함
---
## 4. 사용자 경험(UX)과 '가짜 선택지' (Flavor Choice)
모든 선택이 엔딩을 바꿔야만 할까? 때로는 엔딩을 바꾸지 않는 사소한 선택이 더 큰 몰입감을 줌
**4-1. 선택의 환상 (Illusion of Choice)**
  - 결과에 지장을 주지 않으면서 사용자가 개입하고 있다는 느낌만 주는 장치
  - **사례**: 파티장에 갈 때 [분홍색 꽃신]과 **[파란색 꽃신]** 중 고르게 함. 무엇을 신어도 보안팀에 쫓기는 결말은 같지만, 사용자는 화면 속 콩쥐가 '내가 고른 신발'을 신고 있다는 사실에 만족함
**4-2. 가짜 선택지(Flavor Choice)의 가치**
  - **감정적 피드백**: 엔딩은 같아도 원님이 "그 파란 신발이 예쁘군"이라고 대사 한 줄만 쳐주면 사용자는 자신의 선택이 존중받았다고 느낌
  - **성격 형성**: "무서워도 참는다" vs "무서워서 소리 지른다"의 선택은 결과는 같지만, 사용자가 스스로 '나의 콩쥐'라는 캐릭터성을 정의하게 만듦
---
## 5. 로직 설계: 시스템 뒷단의 작동 원리
사용자가 화면에서 [나노봇 호출] 버튼을 눌렀을 때 벌어지는 일
```javascript
# [사건] 데이터 센터 누수 차단 미션 (2099 네오-콩쥐)

IF 사용자의_선택 == "나노봇_호출":
    # 1단계: 아이템 보유 여부 체크
    IF 인벤토리.has("나노_두꺼비"):
        Outcome = "미션 성공"
        Sync_Rate += 10    # 동기화율(기술력) 상승
        Display = "두꺼비 로봇들이 구멍 난 데이터 망을 완벽히 메웁니다"

    # 2단계: 아이템이 없을 경우의 처리
    ELSE:
        Outcome = "미션 실패"
        Integrity -= 5     # 시스템 오염 혹은 주인공의 멘탈 수치 하락
        Display = "도구 없이는 불가능합니다. 시스템이 과열되어 경고음이 울립니다"

# 결과적으로 바뀐 데이터(Sync_Rate, Integrity)는 다음 사건인 '잔칫집 입장'의 난이도를 결정함
```
