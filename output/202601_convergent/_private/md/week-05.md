# 5주차 스토리 구조 기획
---
### 🎯 수업 목표
- 학습 목표: 작성한 스크립트가 시스템적으로 '작동하는 로직'임을 이해하고, 데이터 경로 맵을 통해 서사적 인과관계와 변수 흐름을 최종 검증
- 핵심 키워드: 데이터 경로 맵 (Data Path Map), 자가점검 (Self-Check), 상세 시퀀스 설계

# 1. 데이터 경로 맵(Data Path Map)
### ① 작성 시점 [설계 직후 ~ 구현 직전]
- 상세 스크립트를 작성하기 전, 전체적인 변수 흐름을 확정하는 단계에서 작성 또는 실개발 전
- 씬(Scene) 간의 유기적 연결성을 시각화하여 논리적 결함을 조기에 발견함
### ② 작성 필요성
- 변수 추적(Variable Tracking): 선택지에 따른 $Sync, Integ, Noise$ 등의 수치 변화가 엔딩까지 유효하게 전달되는지 확인
- 밸런스 조절: 특정 선택지가 너무 유리하거나, 특정 경로에서만 페널티가 과도하게 발생하는 '불균형'을 방지
- 서사적 인과관계 검증: 'A를 선택했기 때문에 B 상황이 발생한다'는 인과관계가 시스템적으로 구현 가능한지 판단

# 2. 자가점검(Self-Check)
### ① 시점 [스크립트 완성 직후]
- 스크립트가 완성된 직후 점검해야 함. 코딩 단계에서 로직을 수정하면 작업 시간이 몇 배로 늘어나지만, 경로 맵 단계에서의 수정은 표 한 줄 고치는 것으로 끝남
- 인과관계 검증: 'A를 선택했기 때문에 B 상황이 발생한다'는 논리가 시스템적으로 구현 가능한지 판단함
- 변수 추적(Variable Tracking): 선택지에 따른 $Sync, Integ, Noise$ 등의 수치 변화가 엔딩까지 유효하게 전달되는지 확인함
- 구조 밸런스 조절: 특정 선택지가 너무 유리하거나, 특정 경로에서만 페널티가 과도하게 발생하는 불균형을 방지함
### ② 점검 필요성
- 선택의 유의미함: [A]를 고르든 [B]를 고르든 결과가 같다면 플레이어는 기만당했다고 느낌. 경로 맵은 두 선택의 '차이'를 수치로 증명함
- 리스크 관리: $Integ$를 계속 깎는 선택만 했을 때, S4에서 게임이 막히지 않고 PZ 강탈 루트로 연결되는지 등의 예외 상황을 체크해야 함
